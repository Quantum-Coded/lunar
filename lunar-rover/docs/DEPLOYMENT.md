# Deploying Lunar Rover for free

Architecture on the free tier:

```
Browser ──> Vercel (frontend, static + Next.js)  ──fetches──>  Hugging Face Space (backend API + terrain tiles + data)
                                                  └ optional: Cloudflare R2 (terrain tiles via CDN)
```

| Part | Service | Why | Free-tier headroom |
|---|---|---|---|
| Frontend (`frontend/`) | **Vercel Hobby** (or Cloudflare Pages) | Zero-config Next.js hosting | Free for personal / non-commercial use |
| Backend + data (`backend/`, `data/processed/`, ~810 MB) | **Hugging Face Spaces** (Docker, CPU basic) | Free 2 vCPU / 16 GB RAM, Git LFS for the big data files | Sleeps after ~48 h with no traffic and wakes on the next visit (about a minute) |
| Tiles (optional speed-up) | **Cloudflare R2** | 10 GB storage free, no download fees | ~235 MB of tiles, well inside the free limits |

> Free-tier limits change. Check each provider's pricing page before launch, especially Vercel's "Hobby" terms
> (non-commercial use only) and Hugging Face's sleep policy.

You need free accounts on **GitHub**, **Hugging Face** and **Vercel** (R2 is optional), plus Git and Git LFS installed
(`git lfs install`).

---

## 0. Before you start: credits and licence

- Open `frontend/src/lib/credits.ts` and fill in the **author and licence of the rover 3D model**. Do not publish without it.
- Add your own `LICENSE` file (MIT is a common choice for the code). NASA/USGS/IAU data keep their own terms; see the About page.
- Edit `frontend/src/lib/developer.ts` with your real bio and links.

## 1. Put the code on GitHub

`data/processed/`, `data-pipeline/raw/`, `node_modules/` and `deploy/space/` are git-ignored (the data is regenerated by the
pipeline and shipped to Hugging Face separately).

```bash
cd lunar-rover
git init   # skip if already a repo
git add .
git commit -m "Lunar Rover"
git branch -M main
git remote add origin https://github.com/<you>/lunar-rover.git
git push -u origin main
```

## 2. Deploy the backend to a Hugging Face Space

1. Make sure the data exists locally: `cd data-pipeline && python build.py --download` (first time only).
2. Build the upload bundle (code + data + Dockerfile + LFS rules):
   ```bash
   python deploy/make_space_bundle.py
   ```
   It writes `deploy/space/`. (Use `--dry-run` to preview. It refuses to overwrite an existing `deploy/space/`.)
3. On huggingface.co: **New → Space**, name it e.g. `lunar-rover-api`, SDK **Docker → Blank**, hardware **CPU basic (free)**,
   visibility **Public**.
4. Create an access token with **write** permission (Settings → Access Tokens). Treat it like a password; never commit it.
5. Push the bundle:
   ```bash
   cd deploy/space
   git init
   git lfs install
   git add .gitattributes
   git add .
   git commit -m "Deploy backend"
   git branch -M main
   git remote add space https://huggingface.co/spaces/<your-hf-username>/lunar-rover-api
   git push space main     # username: your HF username, password: the access token
   ```
   The first push uploads ~810 MB; the Space then builds the Docker image (a few minutes).
6. In the Space → **Settings → Variables and secrets**, add a **variable** (not a secret) after you know your frontend URL (step 3):
   - `LUNAR_CORS_ORIGINS` = `["https://<your-project>.vercel.app"]` (JSON list; add your custom domain too if you have one)
7. Test: open `https://<your-hf-username>-lunar-rover-api.hf.space/api/region`. You should see JSON.

The Dockerfile already sets `LUNAR_ENABLE_DOCS=false` (hides `/docs`) and `LUNAR_TRUST_PROXY=true` (so rate limiting sees real visitor
addresses behind Hugging Face's proxy).

## 3. Deploy the frontend to Vercel

1. vercel.com → **Add New → Project** → import your GitHub repo.
2. **Root Directory:** `frontend`. Framework: Next.js (auto-detected).
3. **Environment variable:** `NEXT_PUBLIC_API_URL` = `https://<your-hf-username>-lunar-rover-api.hf.space` (no trailing slash).
4. Deploy. Copy the resulting `https://….vercel.app` URL.
5. Go back to the Space and set `LUNAR_CORS_ORIGINS` to that URL (step 2.6). The Space restarts in a minute.
6. Open your Vercel URL: the welcome screen should appear, then the rover on the terrain.

The site sends strict security headers (CSP, frame blocking, nosniff) automatically in production builds; the CSP allows only your
own origin plus the API/tile origins taken from the two environment variables above.

## 4. (Optional) Faster tiles with Cloudflare R2

Serving ~11,000 small tile files from the Space works, but a CDN is quicker for visitors far from the Space.

1. Cloudflare dashboard → **R2 → Create bucket** (e.g. `lunar-tiles`) → enable the public `r2.dev` URL (or attach a custom domain).
2. Bucket → **Settings → CORS policy**: allow `GET` from your Vercel URL.
3. Upload `data/processed/tiles/` keeping the folder structure, e.g. with rclone configured for R2:
   ```bash
   rclone copy data/processed/tiles r2:lunar-tiles --transfers 32 --progress
   ```
4. In Vercel add `NEXT_PUBLIC_TILE_URL` = `https://pub-<id>.r2.dev` (the bucket root, no trailing slash) and redeploy.
   Tile paths are `<url>/<z>/<x>/<y>/height.png` and `data.png`.

Free R2 allowances (10 GB storage, 1 M writes and 10 M reads per month) comfortably cover this. Uploading the tiles uses about 11 k writes once.

## 5. Updating later

- **Frontend change:** `git push` to GitHub; Vercel redeploys automatically.
- **Backend code change:** re-run `python deploy/make_space_bundle.py` into a fresh folder (delete the old `deploy/space/` first) and push, or copy the changed files into your existing `deploy/space` checkout and `git push space main`.
- **New data:** re-run the pipeline, rebuild the bundle, push (and re-upload tiles if you use R2).

## 6. Pre-launch checklist

- [ ] Rover model credit and licence filled in (`credits.ts`).
- [ ] `LUNAR_CORS_ORIGINS` is the exact Vercel/custom-domain origin, not `*`.
- [ ] `/docs` returns 404 on the Space (`LUNAR_ENABLE_DOCS=false`).
- [ ] No tokens or `.env.local` files committed (`git status` is clean of secrets).
- [ ] About page loads the dataset list (proves the API is reachable from the browser).
- [ ] Tried on a phone in portrait and landscape.
- [ ] Wake-up test: after the Space has slept, the first visit takes ~1 minute. Consider a note in your post, or ping the API URL before sharing a launch.

## 7. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Loading screen says it could not reach the data server | Wrong `NEXT_PUBLIC_API_URL`, the Space is asleep/building, or CORS origin mismatch (check the browser console). |
| Console: "blocked by CORS policy" | `LUNAR_CORS_ORIGINS` missing your exact origin (scheme + host, no trailing slash, valid JSON list). |
| Console: "violates Content Security Policy" | The API/tile URL in the Vercel env vars differs from the one the browser calls; fix the env var and redeploy. |
| Push to the Space is rejected for large files | Run `git lfs install` before `git add`; make sure `.gitattributes` is committed. |
| HTTP 429 from the API | The rate limiter protects route planning (20/min per visitor by default). Raise it with `LUNAR_ROUTE_RATE_LIMIT='[60, 60]'` if needed. |
| Rover model or textures 404 | The `frontend/public/models/` folder must be committed. |

## Alternatives

If Hugging Face does not suit you: any free VM or container host with ~1 GB disk works (e.g. Oracle Cloud Always Free). Install Python, copy `backend/` and `data/processed/`, run `uvicorn app.main:app --host 0.0.0.0 --port 8000` behind a TLS reverse proxy such as Caddy, and set the same `LUNAR_*` variables. Hosts with only 512 MB RAM and no persistent disk (such as Render's free web service) are a poor fit because of the ~810 MB data set.
